## Items Reviewed and Not Considered Defects

1. **HTTP 409 for duplicate punch-in:** Expected when an attendance record already exists for the employee and attendance date; it protects the unique attendance constraint.
2. **HTTP 404 for an unknown employee:** Appropriate for employee-specific operations when the employee does not exist.
3. **An empty leaderboard:** Valid when no employees have positive late minutes during the selected month.
4. **A null attendance percentage:** Appropriate when an employee has zero working days in the selected month, because the percentage cannot be calculated.
5. **A missing punch-out timestamp:** Expected for an attendance record that has been punched in but not yet punched out.
6. **A 422 response for invalid request data:** Expected for malformed dates, unsupported statuses, invalid timestamps, or invalid correction requests.
7. **An empty trend result:** This may be valid when the selected department has no eligible employees, provided the response follows the API contract.
